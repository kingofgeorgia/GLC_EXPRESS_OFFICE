# GLC EXPRESS OFFICE

Веб-приложение для GLC Express на ASP.NET Web Forms (.NET Framework 4.8), которое объединяет публичный сайт и внутреннюю CRM для обработки заявок, рейсов, клиентов, автомобилей и документов.

## Что есть в проекте

### Публичный сайт

- лендинг с разделами по аукционам, доставке, преимуществам, партнерам, отзывам и контактам;
- мультиязычность `RU / EN / GE` для публичных страниц и шаблонов;
- локализованные страницы `Login`, `AccessDenied`, `About`, `Contact`, `PrivacyPolicy`;
- форма заявки на главной с полями `имя`, `email`, `телефон`, `мессенджер`, `направление`, `тип груза`, `комментарий` и вложением файла;
- language-aware навигация через query string `?lang=ru|en|ge` и cookie;
- публичный контент, редактируемый из CRM: партнеры, отзывы, контактный адрес и часы работы по языкам с fallback на русский.

### CRM

- вкладки `Рейсы`, `Водители`, `Автопарк`, `Автомобили`, `Клиенты`, `Заявки`, `Настройки`;
- CRUD-операции по основным сущностям;
- массовые действия для табличных разделов CRM, включая массовую смену статуса заявок и массовое назначение выбранных автомобилей в существующий рейс;
- связность данных между клиентами, водителями, автопарком, автомобилями и рейсами;
- дашборд CRM с графиками по заявкам и рейсам, фильтром периода `7 / 30 / 90 / 365` дней и drilldown-переходами в отфильтрованные списки;
- отдельная вкладка заявок для лидов с сайта;
- воронка статусов заявок: `Новая`, `Связались`, `Ожидаем документы`, `В работе`, `Оплачено`, `Положительно закрыта`, `Закрыто`, `Отменено`;
- источник заявки и назначение ответственного менеджера;
- внутренние комментарии по заявке с автором и датой;
- компактный список заявок с открытием подробной карточки по клику и кнопкой закрытия карточки;
- вкладка автомобилей, в которую переводятся заявки в рабочих статусах;
- редактируемая карточка автомобиля с выбором уже существующего рейса, проверкой уникальности VIN, историей изменений и сохранением дилера в отдельный справочник для повторного выбора;
- импорт CRM-данных из `.xlsx`, скачивание Excel-шаблона с листом `README` и детальный отчет по результатам импорта;
- CRM-настройки для ролей доступа, дефолтной вкладки, статусов, допустимых расширений файлов, логотипа, публичного контента и JSON-экспорта/импорта настроек.

### Документы и файлы

- хранение служебных документов в защищенной области `App_Data/ProtectedUploads`;
- выдача файлов через `FileAsset.ashx` вместо прямого доступа к файлам;
- отдельная страница `DocumentViewer.aspx` с предпросмотром изображений и PDF;
- аудит открытий и скачиваний документов;
- публичная раздача логотипа через тот же файловый шлюз.

## Архитектурные заметки

- `LiteDB` используется как основное встроенное хранилище;
- публичная локализация реализована в C# через `Services/PublicSiteLocalizationService.cs`, без `.resx`;
- настройки CRM и публичного контента централизованы в `Services/CrmSettingsService.cs`;
- заявки с сайта обслуживаются через `Services/HomeInquiryService.cs`;
- импорт Excel и генерация шаблона вынесены в `Services/CrmExcelImportService.cs` и работают нативно через ZIP/XML без внешних Excel-библиотек;
- справочник дилеров автомобилей вынесен в `Services/CarDealerDirectoryService.cs` и хранится отдельно от основных карточек автомобилей;
- изменения по карточкам автомобилей сохраняются в истории (`CarRecord.ChangeHistory`), включая смену рейса, VIN, дилера и статуса;
- защищенная работа с файлами вынесена в `Services/StoredFileService.cs` и `Services/StoredFileAuditService.cs`;
- для быстрой локальной проверки в репозитории используется `compile.ps1`, поэтому при изменениях стоит сохранять совместимость с C# 5-синтаксисом.

- CRM: `http://localhost:52722/orders`

- `http://localhost:52722/?lang=en`
- `http://localhost:52722/Login?lang=ge`

## Запуск

### Вариант 1: через Visual Studio

1. Откройте `GLC_EXPRESS.sln`.
2. Восстановите NuGet-пакеты.
3. Запустите проект через IIS Express.

### Вариант 2: быстрая локальная проверка кода

Понадобятся:

- .NET Framework 4.8 Developer Pack;
- восстановленные NuGet-пакеты;
- установленный C# compiler из .NET Framework.

Команда для проверки сборки:

```powershell
powershell -ExecutionPolicy Bypass -File .\compile.ps1 -SkipProbe
```

Если нужен compile + HTTP probe:

```powershell
powershell -ExecutionPolicy Bypass -File .\compile.ps1
```

## Авторизация и роли

Пользователи и роли задаются в `Web.config`, а при старте приложения синхронизируются в `LiteDB`.

Страница входа поддерживает `Remember Me`: если браузер уже подставил сохраненные логин и пароль, форма может отправиться автоматически без повторного ручного ввода.

Поддерживаются ключи:

- `Auth.User.<логин>` — SHA-256 хэш пароля;
- `Auth.UserRoles.<логин>` — список ролей через запятую или `;`.

Базовые роли CRM:

- `Admin`;
- `Manager`;
- `Dispatcher`.

Перед production-развертыванием рекомендуется:

- заменить тестовые учетные записи;
- не хранить постоянные пароли в конфигурации приложения;
- проверить состав разрешенных ролей для доступа к CRM и документам.

## Данные и хранение

- основная база: `App_Data/glc-express-office.db`;
- миграционный JSON для старых данных: `App_Data/crm-data.json`;
- JSON-файл заявок с главной: `App_Data/home-inquiries.json`;
- отдельная LiteDB-коллекция `car_dealers` хранит справочник дилеров автомобилей;
- защищенные загрузки: `App_Data/ProtectedUploads/`;
- legacy-папка загрузок: `Uploads/`.

При первом старте приложение:

- создает `LiteDB`;
- синхронизирует пользователей из `Web.config`;
- при пустой базе может подтянуть стартовые данные из `crm-data.json`.

В репозиторий не стоит коммитить локальные данные и пользовательские загрузки:

- `App_Data/*.db`;
- содержимое `App_Data/ProtectedUploads/`;
- содержимое `Uploads/`.
